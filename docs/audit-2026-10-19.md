**Seth behavior audit — 2026-10-19**

Reviewed commit `d5efdca46b37b05abbf8793effba797f95cd20d2` on `main`.
The audit found nine reproducible defects or missing execution safeguards.
P1 means a run can act on the wrong question or an unverified target; P2 means
an execution, interruption, response-validation, or freshness requirement fails.
Findings below describe the audited commit before repair. The audit itself made
no production changes. Subsequent repairs are recorded in
[the 2026-10-20 repair notes](audit-fixes-2026-10-20.md).

**Confirmed findings, in priority order**

1. **P1 — Single mode accepts a replacement question when the control stays in
   the same place.** `capture.py:50-59`, `main.py:249-255`.

   The pre-click check compares only a 49 by 49 pixel square around the target.
   It does not compare the question or the answer text outside that square.
   A local reproduction changed both question text and option text during the
   simulated inference request, while retaining the same radio outline. The
   grounded execution path clicked the replacement question and reported
   `selection_verified: true`. This confirms selection state, not that the model
   answered the question currently displayed.

   Recommended correction: verify stable question and answer content after
   inference, with explicit exclusions for known changing elements and prior
   confirmed selections. Apply this to every provider in Single mode.

2. **P1 — Scroll mode does not recheck all question content after inference.**
   `scroll_navigation.py:423-439`, `wheel_scroll.py:68-94`.

   Before the first selection, `prepare()` checks only the first recorded view
   per scrolling panel. Return navigation also checks the chosen target view.
   Other captured portions may change without comparison against the original
   inference input. A local wheel fixture was captured, then a large block at
   document row 600 was changed while it was off-screen. Preparing target `01`
   still succeeded. Current-frame overlap during return proves consistent
   movement, but does not prove that every section matches its original capture.

   Recommended correction: compare the relevant recorded question sections
   against fresh views before the first answer, including intermediate content,
   using the established overlay masks and alignment rules.

3. **P1 — API and Gemini Single mode can click arbitrary in-frame coordinates
   and report success without selection confirmation.** `ai_client.py:68-71`,
   `web_inference.py:650-667`, `main.py:246-256`.

   These Single paths use coordinate responses rather than numbered controls.
   The single-click execution branch skips `verify_target()` and
   `verify_selection()` when `grounded` is false. The local engine reproduction
   returned coordinates over blank space, with an unchecked radio elsewhere.
   The engine returned `clicked`/Done although the radio remained unchecked.
   The same acceptance also permits a model point over a navigation control;
   the prompt alone supplies that prohibition. This is an existing design gap,
   rather than a new regression in the wheel implementation.

   Recommended correction: use validated control IDs for these provider paths
   and require visible selection confirmation before reporting Done.

4. **P2 — Initial hover shading can reproduce Single mode's `Stopped (1)`.**
   `main.py:165`, `capture.py:50-59`, `capture.py:65-67`.

   Single mode captures its initial baseline before parking the pointer. If a
   later target's row is initially hovered, that shading becomes part of the
   baseline. After the first selected option, selection verification parks the
   pointer and removes the later row's shading. The strict check for the next
   target then rejects the gray-to-white background change. The real engine,
   capture and clicker with a synthetic backend reproduced one confirmed click
   followed by `Remaining answer control changed` and indicator `Stopped (1)`.
   Starting the identical two-checkbox plan without hover selected both options
   and reported Done. No answer text or controls changed in this reproduction.
   This directly reproduces the symptom independently of the earlier persistent
   focus-decoration fix; it does not prove the exact cause of an earlier live run.

   Recommended correction: park the pointer and obtain a settled fresh baseline
   before Single inference, as the wheel discovery path already does. Preserve
   the existing strict change and selection checks.

5. **P2 — Interrupt propagation permits a subsequent press during a 20 ms
   relay window.** `vbox_backend.py:119-136`, `vbox_backend.py:224-225`,
   `vbox_backend.py:248`.

   The SDK helper observes cancellation through a file marker. A separate thread
   publishes that marker at 20 ms intervals. The actual `_input()` and SDK code,
   exercised with `FakeManager`, accepted cancellation after pointer movement
   but still sent the press before the marker arrived. Recorded events were
   button 0 before cancellation, then button 1 and button 0 after cancellation;
   the operation returned success. This finding concerns a press that had not
   been issued when cancellation was requested, not an already issued click.

   Recommended correction: publish cancellation to registered active helper
   markers synchronously when interruption or shutdown is requested. Preserve
   unconditional release after a press begins.

6. **P2 — Contradictory single-click responses silently discard a selection
   list.** `inference.py:200`, `inference.py:225-227`, `main.py:230-256`.

   A response with `action: "click"`, a top-level target ID,
   `selection_type: "multiple_answer"` or `"classification"`, and a two-item
   `selections` list is accepted. The parser grounds the top-level target and
   retains the list without validating it. The execution branch then performs
   one click and ignores the list. Both checkbox and table variants reproduce.
   This is another possible cause of stopping after one choice; it does not
   establish that an earlier live failure had this exact response.

   Recommended correction: enforce action-specific schemas. Reject select-only
   fields on `click` and incompatible top-level click fields on `select`.

7. **P2 — A wheel view's pixel movement can raise `UnboundLocalError`.**
   `scroll_navigation.py:310-325`.

   `_verify_unchanged()` assigns `view` only in the native-scrollbar branch,
   then uses it for alignment in the shared branch. A wheel page shifted by
   one pixel reproduces `cannot access local variable 'view'`. A legitimate
   focus nudge can therefore stop a plan, while an unwanted change is reported
   as a generic internal failure instead of the intended navigation error.

   Recommended correction: resolve the active view before choosing the native
   versus wheel verification path; retain foreground and movement checks.

8. **P2 — Nonstream API completions accept unsuccessful completion metadata.**
   `ai_client.py:193-204`.

   The nonstream parser extracts the first message's text without checking its
   finish reason or refusal/tool-call fields. Mocked HTTP responses containing
   valid click JSON were accepted with `finish_reason` values `length`,
   `content_filter`, and `tool_calls`. The streaming parser already rejects
   incomplete or nonplain decisions. The supplied config uses streaming, so
   this issue affects configurations that disable it.

   Recommended correction: require a completed plain text answer under an
   explicit compatibility policy, with refusal/tool-call rejection matching the
   streaming path.

9. **P2 — Scroll returns reset the timestamp used for the click-age check.**
   `scroll_capture.py:202-211`, `scroll_navigation.py:419-455`,
   `main.py:219-225`, `clicker.py:17-21`.

   Original inference frames are not age-checked during navigation. A fresh
   return screenshot becomes the frame supplied to the clicker. In the local
   reproduction, all original frames were aged by 1000 seconds with a configured
   maximum of 90 seconds. Preparing the target and validating its returned
   frame succeeded because that frame was only 0.22 seconds old. Thus the
   original capture-age bound is enforced differently in Single and Scroll.

   Recommended correction: retain and validate the inference input's original
   timestamp as well as the fresh execution frame. For a capture spanning
   multiple sections, define whether the earliest required section sets the age.

**Current host readiness and limits of verification**

- The application, listener and browser services are active. The listener loaded
  the run/provider/capture shortcuts and Ctrl+Shift+G after desktop startup.
  An initial desktop-not-ready failure recovered on the configured restart.
- Qwen reports ready, including login, model and thinking selection.
- Gemini reports needs login. An earlier journal entry also records a thinking
  label mismatch. That entry alone cannot distinguish a changed selection from
  changed provider page markup.
- The API endpoint responds to the doctor's unauthenticated HEAD probe with
  HTTP 401. This verifies endpoint reachability; credentials and real inference
  were not exercised by that probe.
- The configured VM is stopped. The read-only SDK status command rejected it
  before input. Fresh live capture, scrolling and answer execution could not be
  verified in this audit. Browser integration used isolated local fixtures and
  no model requests; the audit dispatched no VM input.
- SDK cancellation can remain in Cancelling for up to the 30-second helper
  timeout if a native call blocks. The cycle lock prevents another request
  from overlapping cleanup. A hard timeout cannot guarantee release after a
  hung native press; the code correctly reports unknown completion.
- Collection remains bounded to 32 views, 8192 image pixels vertically and
  16 megapixels. Blank or repetitive overlap, unsupported controls, uncertain
  layouts and excess image size stop the run. These are supported limits,
  rather than evidence that arbitrary long pages have been verified.
- Successful captures have no automatic retention bound (`capture.py:29-45`).
  The capture directory currently uses about 480 MiB and the filesystem has
  6.9 GiB available. Long wheel runs retain many intermediate frames, so disk
  usage should be managed before sustained use. Disk-full errors stop capture;
  no old captures were deleted during this audit.

Priority for repairs: question/content identity and provider guard consistency,
then initial hover, cancellation propagation and action schemas, then wheel alignment,
completion metadata and original capture age. Add the corresponding regression
cases before treating a green suite as evidence that these cases are fixed.
